# v1 - מודל חיבור לתוכנות (לפני Computer Use מלא)

> **עדכון (2026-09-23):** מסמך זה תיאר שלב-ביניים בפיתוח (v1.1-v1.2), כולל נסיון קצר עם Supabase Auth ("עדכון v1.2" למטה) שהוסר לגמרי בהמשך. הארכיטקטורה שנבנתה בפועל אחרי השלב הזה (Computer Use מלא, Vision-first) מתועדת ב-`01-ARCHITECTURE.md`. הסעיפים למטה נשמרים כתיעוד היסטורי מדויק של איך הגענו לשם, ועדיין משקפים נכון את שכבת `apps/desktop`'s file-picker/launcher הבסיסית שעדיין קיימת מתחת לשכבת ה-AI Agent.

## החלטה (עדכון v1.2)

לפני בניית שכבת Computer Use מלאה (שנבנתה בפועל בהמשך כ-Vision-first exclusively, ר' `01-ARCHITECTURE.md` §4), הגרסה הראשונה הייתה **מסך חיבורים** - `apps/web` מסך `/integrations`, **בלי התחברות** (ר' עדכון v1.2 למטה), ונתוני החיבור נשמרו מקומית ולא ב-Supabase (ר' הבהרה בסוף עדכון v1.2). לכל אחת מהתוכנות המשרד בוחר את סוג החיבור:

1. **דרך דפדפן** - מדביקים כתובת התחברות, וכפתור "התחבר ל-X" פותח אותה בכרטיסייה חדשה. זהה במהות לדפוס "התחברות לבנק" הקיים ב-SolFinx, בלי שלב ה-Scraping האוטומטי - זה עדיין לא קיים כאן.
2. **מותקן על המחשב** - **אפליקציית Desktop** (`apps/desktop`, Electron) עם לוגו וקיצור-דרך על שולחן העבודה. בתוכה: כפתור "בחר תוכנה" פותח דיאלוג קבצים **מקומי ורגיל** (לא URL, לא עריכת JSON ידנית) לבחירת קובץ ה-exe, וכפתור "פתח את X" מריץ אותו.

### עדכון v1.1 - למה זנחנו את גישת ה-Protocol Handler/PowerShell

הגרסה הקודמת (v1.0) דרשה מהמשתמש להריץ `install.ps1`, ואז **לערוך ידנית קובץ config.json** עם נתיבי exe מדויקים. זה סורבל מדי בפועל. הוחלף באפליקציית Desktop אחת (Electron) שעושה את אותו דבר בלחיצת כפתור על דיאלוג קבצים רגיל - בלי עריכת קבצים, בלי Registry ידני, ועם קיצור-דרך יפה על שולחן העבודה. שני ההיבטים שכן נשמרו מהגרסה הקודמת:

- **החיבור לענן נשאר**: האפליקציה טוענת בתוכה את אותו אתר שרץ ב-Vercel (`BrowserWindow.loadURL`), כך שזו עדיין אותה מערכת, לא כלי נפרד - עדכון עתידי באתר מגיע גם למשתמשי ה-Desktop בלי לבנות מחדש את האפליקציה.
- **אותה החלטת אבטחה**: הנתיב הנבחר **נשמר רק מקומית** (קובץ JSON בתיקיית `userData` של Electron, לא בענן, לא ב-Supabase) ונקרא רק לפי `connectorId` - שום קלט חיצוני (מהדף שנטען) לא יכול לגרום להפעלת קובץ; רק לחיצה על "בחר תוכנה" בתוך האפליקציה עצמה (native dialog, לא HTML) קובעת מה ניתן להפעיל. ר' `02-THREAT-MODEL.md` סעיף Elevation of Privilege.

### עדכון v1.2 - הוסרה דרישת ההתחברות (ובהמשך, כל Supabase)

v1.1 הוסיפה Supabase Auth (magic link) כדי לשייך כל משרד לחשבון משלו. בפועל זה יצר חיכוך גבוה מדי כרגע: שירות המייל המשותף של Supabase מוגבל למספר מיילים נמוך מאוד לשעה (מיועד לבדיקות בלבד), וגם אחרי חיבור SMTP חיצוני (Resend) התגלו עוד מכשולים (הגבלת "רק לכתובת שנרשמה", בלבול בין `localhost` לאתר האמיתי). לבקשת המשתמש - **ההתחברות הוסרה לגמרי**, ובהמשך (ר' `01-ARCHITECTURE.md`) **הוסר Supabase כולו מהארכיטקטורה בפועל**, לא רק שכבת ה-Auth שלו:

- אין `/login`, אין `/auth/callback`, אין `proxy.ts` (Middleware) שחוסם גישה.
- **בזמנו** (שלב הביניים המתואר כאן): הבקשות עברו עם ה-anon key ישירות מול טבלת `connector_configs` ב-Supabase, בלי session/cookies, עם משרד יחיד קבוע (`DEFAULT_OFFICE_ID`) ו-RLS פתוח.
- **המצב בפועל היום - שונה ומפושט עוד יותר**: אין Supabase בקוד כלל יותר. נתיב הקובץ שנבחר לכל תוכנה נשמר ב-**קובץ JSON מקומי** (`connector-paths.json` בתיקיית `userData` של Electron, ר' `05-DATA-MODEL.md` §5) - לא בטבלת `connector_configs`, לא בענן בכלל. יש שרידי SQL תחת `supabase/migrations` בריפו שאינם בשימוש ע"י אף חלק מהאפליקציה.
- **ההחלטה שהובילה לכך**: מכיוון שהטבלה בענן ממילא לא החזיקה מידע רגיש (`type`/`url` בלבד, לא Credentials), והמעבר לאפליקציית Desktop (Electron) איפשר שמירה מקומית פשוטה יותר בלי תלות ברשת בכלל להצגת/עריכת החיבורים - הוסר הצורך בענן לגמרי עבור הנתון הזה.
- **מה זה אומר לעתיד**: אם בעתיד יידרש מצב ריבוי-מחשבים/משרדים שצריך לסנכרן נתיבי חיבור בין תחנות, זו תהיה תוספת חדשה (כנראה ענן), לא שחזור של המנגנון שתואר כאן.

## איך זה עובד טכנית

`apps/desktop/src/main.ts` יוצר חלון עם `preload.ts` שחושף ל-`window.electronAPI` דרך `contextBridge` (עם `contextIsolation: true`, `nodeIntegration: false`, `sandbox: true`). קומפוננטת `apps/web/components/ConnectorCard.tsx`/`IntegrationsGrid.tsx` בודקת אם `window.electronAPI` קיים: אם כן - מציגה את כפתורי הבחירה/הפעלה; אם לא (דפדפן רגיל) - מציגה קישור להורדת האפליקציה (`/download`).

**עדכון - משטח ה-API גדל משמעותית מאז v1.1** (מעבר לשלוש הפעולות המקוריות `getConnectorPaths`/`pickExecutable`/`launchExecutable`), עם הוספת יכולת ה-AI Agent (ר' `09-COMPUTER-USE-AGENT.md`): ניהול הגדרות (`getSettings`/`setXaiApiKey`), ניהול פרטי התחברות שמורים (`getConnectorCredentials`/`setConnectorCredentials`/`clearConnectorCredentials`/`hasConnectorCredentials`), הרצת/עצירת משימות (`runTask`, `stopTask`, אישור/דחייה/מענה על שאלה), קריאת יומן ביקורת (`listRuns`/`getRun`), וסטטוס ריצה נוכחי. הרשימה המלאה והמעודכנת נמצאת ב-`apps/web/types/electron-api.d.ts` (טיפוסי TypeScript מקבילים ידנית ל-`preload.ts`, ר' `01-ARCHITECTURE.md` §2).

בנייה ל-Windows (NSIS, עם קיצור-דרך לשולחן העבודה ואייקון) רצה ב-GitHub Actions על runner של Windows אמיתי (`.github/workflows/build-desktop.yml`) - לא cross-compile מה-Sandbox של הפיתוח - ומפרסמת Release עם קובץ ה-`.exe`.

## מה במפורש **לא** ב-v1.1 הזה (שכבת בחירת-הקובץ הבסיסית)

- הנתיב המקומי לכל תוכנה לא מסונכרן בין מחשבים (אם עובדים מכמה תחנות, בוחרים פעם אחת בכל תחנה) - שיפור עתידי אם יידרש.
- האפליקציה לא חתומה דיגיטלית (Code Signing) - Windows SmartScreen עשוי להציג אזהרה בהתקנה הראשונה. חתימה דורשת תעודה בתשלום, לא נכלל.
- **עדכון - "אין קריאת נתונים אוטומטית" כבר לא נכון**: זה תואר כאן כמגבלת v1.1, אך מאז נבנה בפועל שכבת ה-AI Agent (ר' `09-COMPUTER-USE-AGENT.md`) שכן "קוראת" את המסך (Vision) ומבצעת פעולות בפועל - זה חלק נפרד ומאוחר יותר במונוריפו, לא הרחבה של שכבת בחירת-הקובץ המתוארת במסמך הזה.
- אין Connector מבוסס API/תיעוד רשמי של אף תוכנה - כל 5 התוכנות (Hashavshevet/Hisulit/Shikulit/Konto/Dokka) מטופלות באותה אוטומציית Vision גנרית, בלי אינטגרציה ייעודית לפי סוג, בהתאם למחויבות ב-`07-ASSUMPTIONS-OPEN-QUESTIONS.md` שלא להציג אינטגרציה רשמית בלי תיעוד/גישה/סביבת בדיקה רשמיים.

## איך להריץ מקומית

```bash
# האתר
cd apps/web
npm install
npm run dev     # http://localhost:3100

# אפליקציית ה-Desktop (בטרמינל נפרד)
cd apps/desktop
npm install
AIOP_WEB_URL=http://localhost:3100 npm start
```

הורדת אפליקציית ה-Desktop המותקנת מוסברת במסך `/download` באתר (מפנה ל-GitHub Releases של הריפו).
